# PatSnap Novelty Search Bench

[English](./README.md) | **中文**

用于评估**专利查新检索**（Prior-art Search）系统的 Bench。每个样本提供一篇查询专利的公开号（PN），以及专利审查员引用的 **X 类参考文献**（破坏新颖性的对比文件）作为标注真值。

本 Bench 是**内部全量评测集的 50% 公开版本**，刻意保留了内部评测集的两类样本结构 —— 跨受理局同族扩展样本与单受理局非扩展样本 —— 使检索系统既能在最具信息量的跨同族场景下被深入考察，也能在标准的非扩展场景下作为基线对照。

> 📄 **配套论文**：《Research on Evaluation Methods for Patent Novelty Search Systems and Empirical Analysis》 — Shu Zhang, LiSha Zhang, Kai Duan, XinKai Sun · arXiv [**2508.17782**](https://arxiv.org/abs/2508.17782)（2025-08）。论文系统阐述本 Bench 所采用的数据集构建方法（审查员引用 + 同族技术一致专利的 X 类引用扩展）、评估流程（以发明描述为输入，Top-k 检测率 + Recall 为核心指标）以及按语言 / 技术领域（IPC）/ 受理局三维度的拓展分析框架。
>
> ⚠️ **关于论文的说明。** 数据集自论文（arXiv 2025-08）发表后已做过更新，新版论文撰写中。

### 跨同族扩展子集（170 条）

跨同族扩展子集是**评估查新检索系统时最具信息量的样本切片**：它真实还原了同一发明被多个受理局审查、各受理局审查员独立引用不同 X 类对比文件的场景。检索系统不仅会被对照该查询专利自身的直接 X 引用，还会被对照其跨受理局同族成员审查时发现的 X 引用 —— 这正是一名资深专利专业人员从多角度审视同一发明的方式。

本 170 条切片是**内部全量跨同族扩展集（340）的 50%**，按此比例公开，使公开版与内部评测集的结构分布保持一致。

### 单受理局非扩展子集（399 条）

非扩展子集为**单受理局的标准查新检索基线**，用于评估基础检索能力。每条样本只包含其专利受理审查员直接引用的 X 文献，不做跨同族扩展。本子集（399）是**内部全量非扩展集（约 800）的 ~50%**。

## 适用范围

本 Bench 评估专利查新检索系统的以下能力：

1. **召回** 审查员引用的 X 类破坏新颖性的对比文件
2. **跨受理局匹配** — 对于 `type=family` 样本，查询专利的不同受理局同族成员可能被不同审查员引用不同的 X 文献
3. **排序** 把最相关的对比文件排在结果列表前部

适用于计算标准的检索指标：**top@K 检测率**（X 文献命中率）与 **Recall@K**（X 文献覆盖率）。

## 如何使用查询输入

> ⚠️ **本数据集不打包查询输入文本。**
>
> 每条样本只暴露查询专利的**公开号**（`pn`），不内嵌技术方案文本。对应的查询输入是**该专利说明书中技术方案部分文本**，因文件体积限制不直接打包。
>
> **使用本 Bench 时，请自行先获取每个 `pn` 对应的技术方案文本**，再以此作为查询喂给检索系统。
>
> 推荐来源：**[PatSnap Eureka](https://eureka.patsnap.com/?from=benchmark_github)**（免费试用，提供标准化的技术方案文本）。
>
> 本 Bench 中的 PN 均已转换为 **PatSnap 标准化格式**，可在主流公开专利数据库直接解析。

> **关于公开号（PN）的说明：** 本数据集所有公开号均已转换为 PatSnap 标准化 PN 格式。

## 样本类型说明

### `type=family` — 跨受理局同族扩展（170 条）

每篇查询专利均在多个受理局（CN、US、EP 等）有同族申请；这些样本检测检索系统能否跨不同受理局、跨语言召回 X 文献。`pn_family_x` 与 `pn_family_x_family` 两个字段额外承载了从跨同族审查中发现的 X 引用。同族成员在语义上等同（CC 满分）。

### `type=public` — 单受理局非扩展（399 条）

每篇查询专利只包含其受理审查员直接引用的 X 文献；`pn_family_x` 与 `pn_family_x_family` 字段均为空数组。这些样本作为单受理局标准检索的基线场景。

## Ground Truth 构造

> ⚠️ **GT 构造仅针对 X 类对比文献。**

### 为什么 `type=family` 需要跨同族扩展

同一发明可能在多个受理局申请（如 CN、US）。不同受理局的审查员可能针对同一发明独立引用不同的 X 对比文件。`pn_family_x` 字段承载了来自其他受理局的这些额外 X 引用。评估 `type=family` 样本时，**必须将其并入 GT**。

**示例**：一个发明同时在 CN 和 US 申请。CN 审查员引用了 `CN1234A` 作为 X；US 审查员引用了 `US5678B1` 作为 X。

- `pn_x = ["CN1234A"]`
- `pn_family_x = ["CN1234A", "US5678B1"]`
- GT = `["CN1234A", "US5678B1"]` —— 命中任一即算 hit。

### GT 按样本类型与返回口径

| 返回口径 | `type=family` | `type=public` |
|----------|---------------|---------------|
| **不折叠**（返回单篇专利） | `pn_x` ∪ `pn_family_x` | `pn_x`（`pn_family_x` 为空集） |
| **按同族折叠**（结果按家族聚合） | `pn_x_family` ∪ `pn_family_x_family` | `pn_x_family`（`pn_family_x_family` 为空集） |

`pn_x ∪ pn_family_x` 这同一公式对两类样本统一适用 —— 对 `type=public` 而言，空集并集退化为 `pn_x`。指标脚本逻辑与样本类型无关。

## 评测指标

| 指标 | 公式 | 说明 |
|------|------|------|
| **top@K** | 在前 K 位有 ≥1 个 GT 命中的样本比例 | K = 1, 3, 5, 10, 20, 50, 100 的 X 检测率 |
| **Recall@K** | 前 K 位 GT 命中数 / 总 GT 数 | 同 K 值下的 X 覆盖率 |

### 评分等级（参考）

top@K 与 Recall@K 度量的是不同维度（检测 vs 覆盖），量级也不同，因此分开评级。下表阈值为跨同族扩展场景（`type=family`）的参考目标，其家族扩展后的 GT 显著放大了完整覆盖的难度。

**top@100（X 检测率 —— "是否找到 X？"）**

| 评级 | top@100 | 说明 |
|------|---------|------|
| **A** | ≥ 90% | 优秀 —— 接近审查员级别的全面检出 |
| **B** | ≥ 75% | 良好 —— 可作为高效初筛工具 |
| **C** | ≥ 50% | 可接受 —— 关键案例仍需人工复核 |
| **D** | < 50% | 不达标 —— 模型需要改进 |

**Recall@100（X 查全率 —— "是否找全跨同族的 X 文献？"）**

| 评级 | Recall@100 | 说明 |
|------|------------|------|
| **A** | ≥ 50% | 优秀 —— 跨同族 X 覆盖强 |
| **B** | ≥ 30% | 良好 —— 典型场景下覆盖充分 |
| **C** | ≥ 15% | 可接受 —— 对抗性场景存在缺口 |
| **D** | < 15% | 不达标 —— 覆盖需提升 |

## 数据集构建

### 1. 基础数据层

- 从**所有带有审查员引用 X 类对比文件的发明专利总体**出发，构建抽样框，覆盖多个 IPC 部、多个受理局与近年申请年份
- 准备两条样本路径：
  - **跨同族扩展路径** —— 在至少两个受理局有同族申请的专利（CN、US、EP 等），可聚合跨家族的 X 引用
  - **单受理局路径** —— 仅在单一受理局有 X 引用的专利，作为非扩展基线
- 公开版按 **每条路径 50%** 抽样（跨同族 340 → 170；非扩展约 800 → 399）

### 2. 对齐与处理层

- **文本可比性筛选**：基于权利要求文本初筛
- **语义对齐**：通过自研权利要求一致性模型做跨语义映射
- **技术相似性评估**（仅 `type=family`）：确保跨受理局同族成员技术上等同（CC 满分）
- **降噪**：二次过滤剔除语种差异引入的语义噪声

### 3. Bench 与质量层

- **引用集成**：基于审查员引用的 X 类对比文件
- **规范化**：每个引用源内部独立去重（直接审查员引用、其同族扩展、跨受理局同族成员审查员引用、跨受理局同族扩展四类来源各自独立去重）+ 标识符统一（所有 PN 转为 PatSnap 标准化格式）+ 引用口径对齐。`pn_x*` 与 `pn_family_x*` 四个字段各自去重完成，**但跨字段不再合并去重** —— 同一 PN 可能在多个字段中同时出现。这是设计上的选择，详见下方"指标语义说明"。
- **质量保障**：数据隐私遵循最小披露原则；代表性、稳定性与公平性一致性校验
- **分层抽样**：公开版按 IPC 部 × 语种 做分层抽样，随机种子 = 42 可复现

> ℹ️ **关于跨字段重复的指标语义说明。** 参考指标脚本（`novelty_metrics.py`、`search_metrics.py`）构造 GT 时使用**集合**语义（`pn_x ∪ pn_family_x` 等），任一 PN 跨字段同时出现也只会被计数一次。**跨字段重复不会影响 Hit Rate 或 Recall 的数值。** 在 JSONL 中保留跨字段重复，是为了让每条参考的来源（哪位审查员 / 哪个受理局）可追溯。

    gt = build_gt(sample, collapsed=False)  # GT = pn_x ∪ pn_family_x
    # query_text = fetch_specification(sample["pn"])   # ← 用户自行获取
    # result_list = your_search_system(query_text)

> 一行命令计算指标：`python ../common/metrics/novelty_metrics.py --dataset data/test.jsonl --results your_results.json` —— 脚本不做检索，仅打分。若你的结果按家族折叠，加 `--collapsed`（使用 `pn_x_family ∪ pn_family_x_family` 作为 GT），否则用默认的非折叠 GT。脚本默认运行在 **严格 / leaderboard 口径**，缺失样本计 0；`--allow-partial` 仅供本地调试。

## 局限性

- **仅评估检索环节**：本数据集仅评估检索/召回能力，不涵盖专利分析、无效性判定或 FTO 评估
- **GT 基于审查员引用**：Ground Truth 来自审查员在审查过程中的引用，**并非**所有相关在先技术的完整集合 —— 审查员可能遗漏相关文献
- **时间快照**：数据反映的是采集时点的审查结论，审查后新公开的在先技术未纳入
- **语种覆盖**：仅包含中英文专利。日、韩、德等其他语种的性能无法由本 Bench 推断
- **查询文本未打包**：用户需自行通过公开专利数据库获取每个 `pn` 的说明书文本（参见上方《如何使用查询输入》）
- **公开版为 50% 抽样**：内部全量评测集保留为内部验证；公开版按每条样本路径 50% 抽样，刻意保留内部评测集的分布结构
